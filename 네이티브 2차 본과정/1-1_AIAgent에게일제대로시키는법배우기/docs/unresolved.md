# 미해결 기록

프롬프트를 고쳐도 끝내 해결되지 않은 과업만 남긴다. 성공한 시도는 적지 않는다.

## [미해결 1] 한 턴 6문장 이내 제한 지키기

### 시도한 프롬프트
```
한 턴에 6문장 이상 길게 설명하는 일방적 강의 금지 (혼자 길게 나열하지 말 것)
```
(시스템 프롬프트 v1 금지 사항 1. 입력은 아래 템플릿)
```
[학습자 상태]: 백엔드 개발자 취업을 준비 중인 컴퓨터공학 전공자
[학습 주제]: HTTP와 HTTPS의 차이 및 동작 원리
[요청사항]: 면접에서 핵심만 1분 안에 대답할 수 있도록 기초부터 차근차근 알려줘.
```

### 받은 결과
6문장 제한을 이론 설명 부분에만 적용하는 기준으로 보면 run-log 턴 3, 5는 통과, 턴 9는 경계, 턴 13, 15는 이론 설명이 7문장으로 초과했다. (문장 수는 직접 세어 확정)

### 수정 시도 이력
- v2 금지 사항 1 문구 수정과 규칙 5(길이 점검) 추가 후 재실행(run-log 3-2): 턴 15, 17은 줄었으나 턴 3은 이론 설명을 글머리 4개로 나눠 약 9문장(글머리 제외 약 5문장), 턴 11은 약 7문장. 해결되지 않음 (문장 수는 직접 확정)

### 막힌 이유
길이 제한을 문장 수로 적었더니 AI가 설명을 줄이기보다 짧은 줄 여러 개(글머리)로 나눠 적었다. v2에서 번호 목록은 문장 수에 세지 않는다고 적은 것이 그렇게 나눌 여지를 준 것 같다. 다만 글머리로 나눈 답변이 읽기에 부담스럽지는 않았고, "면접용 1분 답변"처럼 설명, 비유, 예시 답변이 모두 필요한 요청에서는 오히려 쓸모가 있었다. 그래서 글머리 분할을 규칙으로 막을지 허용할지 끝내 정하지 못했다. 엄격하게 막으면 답변이 딱딱해질 것 같고, 풀어 두면 6문장 제한이 의미가 없어진다. 답변 품질을 우선해 유연하게 두는 쪽으로 판단하고 여기서 멈췄다. 어디까지를 이론 설명으로 셀지 기준을 더 정확히 적는 방법은 시도하지 않았고, 그 기준을 AI가 매번 같게 해석하는지도 확인하지 못했다.

## [미해결 2] 대화 중 바뀐 조건(비전공자 청중) 끝까지 유지하기

### 시도한 프롬프트
```
잠깐 조건을 바꿀게! 지금부터는 **개발 지식이 전혀 없는 비전공자 인사팀 면접관** 앞에서 대답해야 하는 상황이야. 이 조건으로 대답해 줘: TLS 1.3 핸드셰이크는 기존 TLS 1.2보다 왕복(RTT) 횟수가 몇 번 줄어들었어?
```

### 받은 결과
턴 11은 비전공자용 설명을 했으나, 이후 턴 13과 15에서 스트림, 시퀀스 번호, 재전송, RFC, IANA 같은 용어가 풀이 없이 다시 나왔다.

### 수정 시도 이력
- v2 규칙 4 추가 후 재실행(run-log 3-2): 턴 15, 17에서 시퀀스 번호, 재전송, IANA 같은 용어가 사라지고 TCP/UDP/QUIC에 쉬운 풀이가 붙음. "TLS 1.3"은 풀이 없이 남음. 대부분 개선되었으나 완전히 해결되지는 않아 미해결로 남김

### 막힌 이유
v2 규칙 4로 대부분 좋아졌지만, 턴 15에서 "TLS 1.3"이 풀이 없이 남았고 턴 17에서는 질문에 RFC가 들어 있어 RFC라는 용어를 그대로 쓸 수밖에 없었다. 전문 용어를 "쓰지 말라"와 "쓰면 풀이를 붙여라" 사이에서 AI가 어디까지 풀이할지 매번 다르게 판단하는 것 같다. 풀이가 필요한 용어 목록을 프롬프트에 미리 줄 수는 있지만, 대화 주제가 바뀔 때마다 목록을 새로 써야 해서 일반적인 해결책이 아니라고 판단해 여기서 멈췄다.
